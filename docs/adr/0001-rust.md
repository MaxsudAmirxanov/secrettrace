# ADR-0001: Rust для сервера, CLI и агентов

**Статус:** принято (2026-11-19)

## Контекст
Первоначальный дизайн предлагал Python (FastAPI). Владелец проекта выбрал Rust ради производительности.

## Решение
Весь backend — Cargo workspace на Rust 1.89 (edition 2024):

| Задача | Выбор |
|---|---|
| HTTP API | axum 0.8 + tower-http |
| БД / миграции | sqlx 0.8 (Postgres), SQL-миграции в `migrations/`, встраиваются в бинарник |
| Криптография | RustCrypto: `sha2`, `hmac`, `subtle`; `zeroize` и `secrecy` для открытых значений |
| Логи | `tracing` + JSON-вывод |
| CLI | clap |
| Git-скан (этап 7) | `git cat-file --batch` по уникальным blob'ам; `gix` рассматривается как замена позже |

## Последствия
- Сканер, CLI и агент поставляются одним статическим бинарником без интерпретатора на хостах и в CI.
- Нормализация и digest живут в одном крейте (`st-core`), который собирают и сервер, и клиенты, так что расхождения между реализациями исключены. Браузер (TS) сверяется с общими тест-векторами в `testdata/`.
- Типы `Zeroizing`, `SecretString`, `Digest` и `Fingerprint` с урезанным `Debug` закрывают требование «секреты не попадают в логи» на уровне компилятора, а не соглашений.
- Время сборки выше, чем у Python; в CI это смягчает кэш (`Swatinem/rust-cache`).
- Используется sqlx 0.8, а не 0.9: API стабилен и хорошо известен. Обновление — отдельной задачей.
- Запросы к БД проверяются интеграционными тестами, а не макросами `query!`: макросам нужна живая БД во время сборки. Переход на offline-режим (`cargo sqlx prepare`) возможен позже.
